# Implementation Plan — Ledger OCR MVP

This task was decomposed into FEAT artifacts under `.agents/tasks/ledger-ocr-mvp/` (task.json, context.json, features/FEAT-00{1..5}.json) because it spans several independently-verifiable systems (data/seed, auth+tenancy+invitations, expense/review workflow, OCR+classification+export, i18n+PWA+polish), each of which can build and verify green on its own before the next begins. The workflow tail has been replaced with one `wf-coder` step per FEAT (sequential, same worktree) followed by a fixer+reviewer convergence loop and a finalize step. This plan.md is the durable fallback: if the FEAT tail could not be installed, work through the items below in order with the existing implement-and-review loop.

Key design decisions made during exploration (see context.json for full detail and file citations):
- Next.js 16 renamed `middleware.ts`/`export function middleware` to `proxy.ts`/`export function proxy` (confirmed in `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md`). All role-based route protection goes in `src/proxy.ts`.
- next-intl 4.14.9 is used in "without i18n routing" mode (cookie/profile-based locale, not `[locale]` URL segments) since this app's routes are role-based (`/admin`, `/app`), not localized paths.
- @serwist/next 9.5.13's `withSerwistInit` default export wraps `next.config.ts`; the service worker lives at `src/app/sw.ts` using `defaultCache` from `@serwist/next/worker`.
- @typesafe-ai/sdk 0.6.0's `TypeSafeClient.systemOne()` takes a map of named `choice`/`noul`/`score` questions — one call per classification, answering category (choice), BTW rate (choice over '0'/'9'/'21'), and deductible (noul) together, per the task's "ONE systemOne call" requirement.
- OpenAI SDK v6.49.0's `chat.completions.create` with a `type: 'image_url'` content part (base64 data URI) is the Vision extraction mechanism, following the pattern read from the sibling reference project (not imported, re-implemented locally).
- All three external integrations (OpenAI, TypeSafe, Cloudinary) must detect placeholder/unset API keys and fail with a clean 5xx JSON response rather than crashing, per the task's explicit requirement.
